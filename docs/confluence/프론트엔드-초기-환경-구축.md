> 회의 목적: PLKIT 데스크톱 대시보드의 프론트엔드 초기 환경 구성 결과와 다음 개발 기준을 공유한다.

## 1. 한눈에 보기

| 항목          | 결정 사항                                                             |
| ------------- | --------------------------------------------------------------------- |
| 대상          | PLKIT 스마트팜 데스크톱 대시보드                                      |
| 기술 스택     | Electron, React 18, TypeScript, Vite, electron-vite, ESLint, Prettier |
| 패키지 매니저 | npm                                                                   |
| 현재 화면     | `PLKIT Desktop Dashboard` 초기 상태 화면                              |

| 제외 범위     | 센서/API/MQTT/장치 제어/영상/AI/배포 기능                             |

## 2. 구현 결과

### Electron 프로세스 분리

Electron은 역할이 다른 세 영역으로 분리했습니다.

| 영역 | 위치 | 책임 | 주의 사항 |
| --- | --- | --- |
| Main | `src/main/index.ts` | 앱 생명 주기, 창 생성, 개발·프로덕션 renderer 로드 | Node.js와 Electron API 사용 가능 |
| Preload | `src/preload/index.ts` | 향후 renderer에 안전한 IPC API를 노출할 경계 | 현재는 API를 노출하지 않음 |
| Renderer | `src/renderer` | React 화면과 FSD 기능 코드 | Node.js API 직접 사용 금지 |

`BrowserWindow`에는 다음 보안 기본값을 적용했습니다.

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- 개발에서는 로컬 Vite 개발 서버, 프로덕션에서는 로컬 빌드 파일만 로드

### 초기 실행 화면

Dashboard 페이지는 앱이 정상 실행되었음을 보여 주는 최소 화면입니다.

- 제목: `PLKIT Desktop Dashboard`
- 메시지: 스마트팜 기능을 아직 연결하지 않았음을 명확히 표현
- 상태: `Application ready`는 앱 시작 상태만 의미하며 센서·장치 연결 상태를 의미하지 않음

## 4. FSD 적용 범위와 기준

FSD는 React 화면이 동작하는 `src/renderer`에만 적용했습니다. `main`과 `preload`는 Electron 런타임 코드이므로 FSD에 포함하지 않습니다.

### 레이어별 역할

| 레이어     | 현재 역할                                  | 앞으로 둘 코드 예시                      |
| ---------- | ------------------------------------------ | ---------------------------------------- |
| `app`      | 앱 진입점, 전역 스타일, 전역 Provider 위치 | 라우터, 전역 상태 Provider, 테마         |
| `pages`    | 사용자에게 보이는 완성 페이지              | Dashboard, 설정, 커뮤니티 페이지         |
| `widgets`  | 여러 기능과 엔티티를 조합한 화면 블록      | 센서 요약 패널, 장치 제어 패널           |
| `features` | 사용자가 수행하는 단일 행동                | 팬 켜기/끄기, 필터 변경, 데이터 내보내기 |
| `entities` | 스마트팜 도메인 모델과 표시 단위           | 센서, 장치, 농장, 예측 데이터            |
| `shared`   | 특정 도메인에 종속되지 않은 재사용 코드    | API 기반 도구, 공용 타입, 범용 UI        |

### 의존성 방향

```text
app → pages → widgets → features → entities → shared
```

- 왼쪽의 상위 레이어는 오른쪽의 하위 레이어를 사용할 수 있습니다.
- 하위 레이어가 상위 레이어를 import하는 역방향 의존성은 금지합니다.
- 각 슬라이스는 `index.ts`를 공개 API로 사용합니다.
- ESLint가 `@app`, `@pages`, `@widgets`, `@features`, `@entities` 별칭을 통한 역방향 import를 검사합니다.

### 현재 적용된 FSD 예시

```text
src/renderer/app/index.tsx
  └── @pages/dashboard 공개 API를 import
        └── pages/dashboard/index.ts
              └── ui/dashboard-page.tsx
```

현재 Dashboard는 `pages` 레이어에 있으며, 이후 센서 데이터 모델은 `entities`, 장치 제어 행동은 `features`, 여러 패널을 조합한 Dashboard 블록은 `widgets`에 추가합니다.

## 5. 경로 별칭

| 별칭          | 실제 경로                 |
| ------------- | ------------------------- |
| `@app/*`      | `src/renderer/app/*`      |
| `@pages/*`    | `src/renderer/pages/*`    |
| `@widgets/*`  | `src/renderer/widgets/*`  |
| `@features/*` | `src/renderer/features/*` |
| `@entities/*` | `src/renderer/entities/*` |
| `@shared/*`   | `src/renderer/shared/*`   |

TypeScript와 Vite에 동일하게 구성했으므로 편집기 검사와 실제 런타임 해석이 일치합니다.
